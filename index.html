The problem

Your repo telesto has been on disk for three months. You didn't find it last Tuesday.

Navigation tools assume you remember what you're looking for. You don't. And the moment a repo doesn't exist yet, you leave the tool and build the path by hand.

01

Names that mean nothing

Every workspace has telesto, pursuit, mms, openslo. Fuzzy search only matches strings you already remember — and at company scale, nobody does. The question is never "what is it called," it's "which one does the thing."

02

Creation means hand-building a path

Every new repo is the same ritual: cd, mkdir -p, git clone — thirty seconds, repeated across a year of projects, with the one rule that matters (where it goes) living entirely in your head.

03

Worktrees you can't reach

Your actual work happens in a worktree a level too deep for the picker. You organize for worktrunk, then can't land in it without typing the path again.

How it works

Describe the work. Land in the directory.

Deterministic where a machine should be, judgment only where a human is the source of truth.

01 — describe

Say what you're doing

In plain words. "the one that handles the auth group sync," "where I set up the taint eviction fix." You don't need the repo's name — that was always the part you forgot.

02 — choose

One fast model call decides

repos builds a tiny descriptor per repo (name, remote, README heading, branches, recent commits) and asks Jev — a ~150 ms type-safe decision model — which repo matches, with a calibrated confidence. No index to build, nothing to go stale between commits.

03 — land

You're in the repo

Confident? It prints the path and the rl hook moves you. Not confident, or the description matches nothing? No silent wrong jump — it falls back to the ordinary r picker, so a miss is never a dead end.

Everything else

What changes when you install it tomorrow

repos launch "..."

Find it by what it does

Not by what it's called. This is the whole point — the description is the interface.

repos clone · init

One command to clone. It picks the folder.

Give it an owner/repo or a remote and the path is computed, never typed.

worktrunk

Your worktrees show up

List and enter them from the same picker. repos picks the repo, worktrunk picks the branch.

r — untouched

The fast path stays instant

Dozens of jumps a day, zero model, ranked by what you actually work in. Nothing slows the path you already know.

repos doctor · adopt

It finds misplacements, and fixes them

Reports stray directories, empty owners, repos living off-depth — then relocates them for you.

opt-in, metadata-only

Private by default, online by choice

r never leaves your machine. launch sends only light metadata — names, remotes, branch and commit titles — never file contents, and only when you give it a Jev key. No key, no call: it's just r.
